# Установка и запуск

> English version: [setup.md](setup.md)

## Что нужно на компьютере

Только **Docker Desktop** с бэкендом WSL2. Python и Node на хост ставить не
нужно — они требуются лишь для разработки и тестов (см.
[development.ru.md](development.ru.md)).

Проверено на: Windows 10 Pro 22H2 (сборка 19045), Docker 29.1.3,
Docker Compose 2.40.3, NVIDIA RTX 3070 8 ГБ, драйвер 591.74.

> В README указана Windows 11. Windows 10 22H2 официально поддерживается
> Docker Desktop, но её потребительская поддержка Microsoft закончилась
> 14.10.2025, а Docker поддерживает Windows только в пределах окна обслуживания
> Microsoft. Практический вывод: зафиксируйте версию Docker Desktop и не
> включайте автообновление, либо планируйте переход на Windows 11.

## Первый запуск

1. Установить Docker Desktop, включить бэкенд WSL2 и поддержку GPU
   (Settings → Resources → WSL integration; драйвер NVIDIA свежий).
2. Скопировать файл настроек:
   ```powershell
   copy .env.example .env
   ```
   Значения по умолчанию годятся для локального запуска. Сохраняйте файл в
   UTF-8 — в нём русские комментарии.
3. Поднять систему:
   ```powershell
   docker compose up -d
   ```
4. Открыть <http://localhost:8000>.

Первый `up` создаёт базу, применяет миграции и начинает скачивать модель
`qwen3:8b` (≈5.2 ГБ). **Загрузка модели ничего не блокирует** — она идёт в
отдельном одноразовом контейнере `ollama-init`, а команда `up -d` возвращает
управление через несколько секунд. Прогресс:

```powershell
docker compose logs -f ollama-init
```

Состояние `ollama-init  Exited (0)` в `docker compose ps` — **нормальное**: это
разовая задача, которая завершилась успешно. Готовность модели видна в
`GET /health` в поле `ollama_model`.

## Ежедневное использование

```powershell
docker compose up -d      # включить
docker compose down       # выключить
```

Данные живут в именованных томах Docker и переживают выключение.
`docker compose down -v` **удаляет тома** — в том числе базу и скачанную модель.

## Проверка, что всё работает

```powershell
docker compose ps                              # все сервисы healthy
curl http://127.0.0.1:8000/health               # {"status":"ok","db":"ok",...}
docker compose exec ollama nvidia-smi           # видна RTX 3070
docker compose exec db psql -U ration -d ration -c "\dx"   # vector, pg_trgm
```

## Доступ с телефона по домашней сети

По умолчанию порт публикуется только на `127.0.0.1` — приложение доступно
исключительно с этого ПК. Чтобы открыть доступ из домашней сети, в `.env`:

```
WEB_BIND_IP=0.0.0.0
```

и `docker compose up -d`.

> **Отклонение от ТЗ.** В ТЗ этот переключатель назван `WEB_EXPOSE=0|1`.
> В Docker Compose нет условных выражений в секции `ports`, а очевидные обходные
> варианты ошибаются **в сторону открытия доступа** (пустой `host_ip` означает
> `0.0.0.0`) — недопустимо для приложения без авторизации. Поэтому переключателем
> служит сам адрес привязки.

Одного этого мало: нужно также разрешить входящие подключения на TCP 8000 для
`com.docker.backend.exe` в брандмауэре Windows и убедиться, что домашняя сеть
классифицирована как **частная**.

**Наружу в интернет приложение публиковать нельзя** — в нём нет авторизации.

## Автозапуск после перезагрузки

У всех сервисов стоит `restart: unless-stopped`, так что после перезапуска
Docker они поднимутся сами. Но Docker Desktop — обычное приложение и стартует
**при входе пользователя в систему, а не при загрузке компьютера**. Включите
Settings → General → «Start Docker Desktop when you sign in». Полностью
автоматический запуск после перезагрузки без входа в систему невозможен.

## Место на диске

Docker Desktop хранит образы и тома в `ext4.vhdx` на диске C:. Проекту нужно
25–30 ГБ (образ приложения ~0.4 ГБ, образ Ollama ~3 ГБ, модель 5.2 ГБ, Postgres,
до 14 ГБ дампов). Если на C: мало места, перенесите хранилище:
Settings → Resources → Advanced → Disk image location.

## Память WSL2

По умолчанию WSL2 отдаёт контейнерам около половины оперативной памяти. Для M1
этого достаточно, но бенчмарк моделей в M5 (`qwen3:14b`, `gpt-oss:20b`) уходит в
гибридный режим GPU+CPU и упрётся в лимит. Создайте `%USERPROFILE%\.wslconfig`:

```ini
[wsl2]
memory=16GB
processors=8
swap=8GB
```

После правки нужен `wsl --shutdown` (он останавливает все контейнеры — делайте
это до `docker compose up`).

## Безопасность локальной машины

Проверьте, что в Docker Desktop **выключена** опция
«Expose daemon on tcp://localhost:2375 without TLS». Она открывает
неаутентифицированный доступ к Docker API, что равносильно правам root на
машине. Проекту она не нужна.
