# Проект «Рацион» — умный планировщик питания и закупок

Локальное (self-hosted) веб-приложение: база рецептов с умным поиском, ежедневный
парсинг цен ближайших магазинов (Пятёрочка, Лента), рацион на 3–4 дня под калораж
каждого члена семьи и оптимальный список покупок — весь в **одном** магазине,
том, где корзина целиком выйдет дешевле, и так, чтобы еда не выбрасывалась.
Считает потраченные деньги и фактические КБЖУ.

Учебные цели: практика RAG (эмбеддинги + pgvector + retrieval), локальный
инференс LLM, современный типизированный фронтенд (React + OpenAPI).

> English version: [README.md](README.md). Рабочие ТЗ модулей (`TZ-M*.md`)
> ведутся только на русском.

## Целевое окружение

- **Хост**: стационарный ПК Windows 11, RTX 3070 8 ГБ VRAM, Docker Desktop (WSL2).
- **Пользователи**: одна семья. Интерфейс — браузер: `http://localhost:8000`.
  Опционально — доступ с телефонов по домашней сети (`WEB_EXPOSE=1`).
- **Всё в Docker**: Postgres, Ollama (с пробросом GPU), API+веб, планировщик задач —
  один `docker compose up -d` включает всю систему, `docker compose down` выключает.
- Авторизации нет: приложение живёт только в локальной сети и наружу не публикуется.

## Стек

| Слой | Технология |
|---|---|
| Язык бэкенда | Python 3.12 |
| API-сервер | FastAPI + uvicorn |
| БД | PostgreSQL 16 + pgvector (в Docker) |
| Миграции | Alembic |
| ORM | SQLAlchemy 2.x (async) |
| Фронтенд | React 18 + Vite + TypeScript (strict) |
| UI-библиотеки | Mantine (компоненты), TanStack Query (данные), Recharts (графики) |
| Контракт API | OpenAPI (FastAPI) → openapi-typescript → типы фронтенда |
| LLM | Ollama локально, модель конфигурируема (`OLLAMA_MODEL`, default qwen3:8b; бенчмарк — TZ-M5); абстракция позволяет Claude API / без LLM |
| Эмбеддинги | sentence-transformers `intfloat/multilingual-e5-small` на CPU |
| Оптимизация закупки | Google OR-Tools (CP-SAT) с fallback на жадный алгоритм |
| Планировщик задач | APScheduler (ночной парсинг цен) |

```
│          │                  │                   │                  │                 │
│          └──────────────────┴────────┬──────────┴──────────────────┘                 │
│                                      ▼                                               │
│                     [PostgreSQL + pgvector (Docker)]                                 │
│                                      ▲                                               │
│  5ka / lenta ◄── ночной парсинг ── [M3 Парсеры магазинов + APScheduler]              │
│                                                                                      │
│  [Ollama :11434  Qwen3-8B]  ◄── LLMProvider (абстракция, съёмный слой)               │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

Два ключевых принципа:

1. **Вся математика — детерминированный код** (калории, КБЖУ, ужарка, оптимизация
   закупки). LLM — тонкая съёмная прослойка: понять свободный текст пользователя →
   параметры; результат планировщика → человеческое объяснение. Приложение обязано
   полностью работать в кнопочном режиме без LLM (`NoLLMProvider`).
2. **API-first**: веб-интерфейс — лишь один из клиентов REST API. Telegram-бот или
   мобильное приложение в будущем добавляются как ещё один тонкий клиент,
   без переписывания ядра.

## Языки и документация

- Код, docstrings, сообщения коммитов — **английский**.
- Публичная документация (`README`, `docs/`) — двуязычная:
  `<имя>.md` (EN) + `<имя>.ru.md` (RU).
- Рабочие ТЗ (`TZ-M*.md`) — только русский.
- Документация API генерируется автоматически: Swagger UI на `/docs`
  (из OpenAPI-схемы FastAPI).

## Общие соглашения (для всех модулей)

- Все количества продуктов в БД — в **граммах/миллилитрах сырого продукта**.
  КБЖУ хранится на 100 г сырого; готовый вес выводится через коэффициенты M4.
- Деньги — в копейках (int), чтобы не ловить ошибки float.
- Все внешние вызовы (5ka API, Ollama) — с таймаутами и ретраями, их падение
  не должно ронять систему.
- Каждый модуль поставляется с тестами на свою математику (pytest); особенно
  M4 (формулы) и M5 (оптимизатор). Фронтенд — strict TypeScript.
- Каждый модуль обновляет документацию в `docs/` (EN + RU).
- Секреты и локальные настройки — только в `.env`, в git не попадают.

## Данные и бэкапы

- Все данные живут в Docker volumes на локальном диске ПК. Data-каталог Postgres
  на сетевой шаре NAS размещать **нельзя**: сетевые ФС не дают честных файловых
  блокировок — это путь к повреждению базы; к тому же ARM-CPU и 1 ГБ RAM
  домашнего NAS не потянут Postgres+pgvector.
- Опциональный вариант с NAS: ночное задание scheduler делает `pg_dump`; если
  в `.env` задан `BACKUP_DIR` (смонтированная SMB-шара NAS) — дамп копируется
  туда (ротация — TZ-M1). Не задан — дампы лежат в локальном volume.
- Восстановление: `scripts/restore.ps1 <дамп>` (TZ-M1).

## Быстрый старт (делается один раз в M1)

1. Установить Docker Desktop (backend WSL2), включить поддержку GPU
   (Settings → Resources → WSL integration; драйвер NVIDIA свежий).
2. `copy .env.example .env` (дефолты подходят для локального запуска).
3. `docker compose up -d` — поднимает ВСЁ: Postgres, Ollama (сам скачает
   qwen3:8b при первом старте, ~5.2 ГБ), API с миграциями, планировщик задач.
4. Открыть `http://localhost:8000` — мастер первого запуска создаст семью.

Ежедневное использование: `docker compose up -d` — включить,
`docker compose down` — выключить. Данные БД живут в volume и переживают
выключение. Python и Node на хост ставить не нужно — всё в контейнерах
(локальная установка нужна только для разработки/тестов).
