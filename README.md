# Рацион

Локальный планировщик питания: семья, техника, ограничения, КБЖУ, бюджет,
холодильник, сроки хранения и закупка реальных упаковок. Актуальное ТЗ:
[ТЗ/TZ-v2.md](ТЗ/TZ-v2.md).

Сейчас работают сборщик «Ленты», импорт локальных PDF-рецептов и первая полезная
версия локального web-приложения.

## Что работает

- гостевая сессия API официального приложения и обязательная проверка адреса;
- продуктовые категории, вода/напитки, готовая еда и алкоголь;
- пагинация по `total/offset`, дедупликация по внешнему ID;
- фасовка, наличие, лимит продажи, обычная, карточная, акционная и персональная
  цена как разные поля;
- PostgreSQL-схема `lenta_store`, ежедневная история цен и JSONL-снимки;
- постепенная загрузка состава, КБЖУ и условий хранения;
- ежедневный запуск в 03:00 по Москве;
- изображения, видео и отзывы не сохраняются;
- импорт рецептов из локальных PDF-книг по конвейеру TZ-M2R: постраничное
  извлечение с сохранением вёрстки (PyMuPDF + OCR), очистка колонтитулов,
  экспорт 4-страничных окон (`export-windows`), распознавание окон сессиями
  Claude по подписке (без API-ключа) и загрузка результатов в БД с валидацией,
  дедупликацией и статусами `ready`/`needs_review` (`load-extracted`);
- разметка библиотеки сессиями Claude по подписке: кухня (12 кодов) и тип
  блюда (суп/салат/стейк/рагу и ещё 19) у каждого рецепта; фильтры в списке
  рецептов и выбор кухонь в форме меню появляются автоматически по фасетам;
- планировщик меню TZ-M5R на CP-SAT (OR-Tools): оптимизация по всему горизонту
  сразу (стоимость по каталогу «Ленты», использование запасов до истечения
  срока, разнообразие — блюдо не чаще 2 раз и не в соседние дни, бюджет и
  дневные калории как мягкие ограничения), аллергии и исключения — через
  словарь синонимов `ingredient_synonyms`, замена отдельного блюда с тремя
  альтернативами и пересборкой списка покупок; при недоступности решателя —
  детерминированный жадный запасной алгоритм;
- оценки рецептов (звёзды 1–5) — любимое планировщик ставит чаще; КБЖУ блюд
  считается из карточек товаров «Ленты» (заполняются ночными догрузками);
  товары в списке покупок и карточках рецептов — кликабельные ссылки на
  lenta.com; вода и лёд в список покупок не попадают.

## Попробовать web-приложение

Приложение уже входит в Docker Compose и доступно только с этого компьютера:

```powershell
docker compose up -d db scheduler web
```

Откройте [http://localhost:8080](http://localhost:8080), создайте локальный
аккаунт и затем:

1. в «Плане питания» выберите период и бюджет — меню составится сразу, даже
   если техника и ограничения ещё не заданы;
2. в «Запасах» внесите продукты и сроки годности: планировщик сначала
   израсходует то, что скоро испортится;
3. в «Настройках» уточните состав семьи, коэффициенты порций, технику и
   ограничения в питании;
4. откройте меню, рецепты и список покупок, отмечая купленное прямо в таблице.

Экраны адресуются хешем, поэтому «Назад» и прямые ссылки работают:
`#/plan`, `#/plan/<id>`, `#/recipes`, `#/recipes/<id>` (открывает карточку
рецепта поверх списка), `#/inventory`, `#/products`, `#/settings`. Фильтры
списков тоже попадают в адрес — `#/recipes?q=плов&meal=lunch&ready=1`.

Тема оформления следует системной и переключается вручную в
«Настройках → Оформление».

В разделе «Продукты Ленты» показаны доступные позиции с обычной, карточной и
акционной ценой. Для плана можно выбрать стратегию:

- `Экономно` — более дешёвые подходящие блюда и товарные варианты;
- `Сбалансированно` — средний ценовой уровень;
- `Премиально` — более дорогие подходящие варианты.

Названия локальных источников рецептов не выводятся в web-интерфейсе и не
передаются его API; для сверки остаётся только номер страницы.

Web-версия хранит пароль как Argon2id-хеш, использует отзываемые HttpOnly-сессии
и CSRF-защиту со сравнением за постоянное время. Вход ограничен пятью попытками
в минуту на пару «адрес + логин» (ответ 429 с `Retry-After`); счётчик живёт в
памяти процесса, поэтому при переходе на несколько воркеров uvicorn его нужно
будет вынести наружу. Любой ответ несёт `Content-Security-Policy: default-src
'self'`, `X-Content-Type-Options`, `X-Frame-Options` и `Referrer-Policy` — из-за
CSP в интерфейсе нет ни одного инлайнового скрипта или атрибута `style`. Все
семейные записи разделены по семье и роли, чужой идентификатор даёт 404, а не
403. История планов и действий хранится в PostgreSQL. Одноразовая команда для
привязки Telegram уже предусмотрена, но сам бот включается после добавления
токена BotFather.

### Правка интерфейса

`app/web/static` смонтирован в контейнер только на чтение, поэтому правки CSS и
JS видны по F5 без `docker compose build`. Пересборка нужна только для
изменений в Python. Интерфейс собран на ES-модулях без сборщика и npm; шрифт
Inter лежит в `app/web/static/fonts/` — приложение работает полностью офлайн.

Ограничения текущей версии: часть импортированных рецептов остаётся в статусе
`needs_review` (неполные ингредиенты или шаги — уточняются вручную или повторным
распознаванием), в интерфейсе они помечены бейджем «Черновик» и скрываются
переключателем «Только проверенные»; время
приготовления и число порций есть не у всех рецептов и не выводятся, если их
нет; калорийность оценивается по небольшому прозрачному справочнику плюс
карточкам «Ленты» — блюда с неполным расчётом помечаются бейджем
«ккал: N из M ингредиентов»; КБЖУ загружены примерно для 11% товаров каталога
(детальные карточки догружаются каждую ночь) и показываются только там, где
есть; стоимость считается только для товаров, уже попавших в локальный каталог
«Ленты». Эти оценки явно помечены в интерфейсе и не являются медицинской
рекомендацией.

Замена отдельного блюда в плане работает: кнопка «Заменить» предлагает три
альтернативы для слота и пересобирает список покупок (`ТЗ/TZ-M5R-PLANNER.md` §3).

Контракт мобильного API может меняться. Версия заголовков вынесена в `.env`, а
сборщик делает ограниченные повторы и не обходит защиту или авторизацию.

## Проверка

```powershell
python -m unittest discover -s tests -v
docker compose --profile manual config --quiet
```

Тесты веб-слоя (`tests/test_web_api.py`) поднимают приложение через
`create_app(repository=...)` с репозиторием в памяти — Postgres и сеть не нужны.
Им требуются `argon2-cffi` и `httpx` (`pip install -e .[dev]`); без `httpx`
файл целиком пропускается, а не падает.

Короткий живой проход (намеренно имеет статус `partial`, потому что ограничен
одной страницей из полного `total`):

```powershell
docker compose up -d db
docker compose --profile manual run --rm collector `
  --category molochnye-produkty-yajjco-3 `
  --max-pages 1 `
  --detail-limit 3
```

Проверенный результат: 40 товаров, 40 цен по Карте №1 и 3 подробные карточки с
составом. Файлы появляются в `data/lenta/`.

## Ночной режим

```powershell
docker compose up -d db scheduler
```

Первый полный проход тяжелее последующих. Параметры находятся в
`.env.example`; статические карточки догружаются партиями через
`LENTA_DETAIL_LIMIT`.

Спецификация регистрации, ролей, общей семьи и привязки Telegram:
[ТЗ/TZ-M1-AUTH.md](ТЗ/TZ-M1-AUTH.md). Действующий конвейер импорта PDF-рецептов
(окна + распознавание сессиями Claude): [ТЗ/TZ-M2R-RECIPES-LLM.md](ТЗ/TZ-M2R-RECIPES-LLM.md);
исходное ТЗ импорта и пропорционального расчёта порций:
[ТЗ/TZ-M2-RECIPES.md](ТЗ/TZ-M2-RECIPES.md).
