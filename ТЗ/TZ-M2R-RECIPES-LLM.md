# TZ-M2R — Переимпорт рецептов с распознаванием через Claude (Haiku, по подписке)

> **Для исполнителя (сессия Claude Code).** Это самодостаточное ТЗ. Выполняй задачи
> из раздела 9 по порядку, отмечая чек-боксы. Не изобретай другую архитектуру:
> все решения приняты и зафиксированы здесь. Старый парсер
> (`app/recipes/parsing.py`) НЕ чинить по мелочи — он заменяется целиком.
> Модули `app/store/*` и `app/web/*` в этом ТЗ не трогать (кроме задачи T10).
>
> **Ключевое решение:** распознавание текста рецептов выполняет НЕ код через
> Anthropic API, а отдельная сессия Claude Code на модели Haiku по подписке
> пользователя. Код готовит файлы-окна и загружает результаты; сессия Haiku
> работает по промту `ТЗ/PROMPT-HAIKU-RECIPES.md`. API-ключ не нужен.

## 1. Проблема

Импорт PDF-книг (787 рецептов, 6353 ингредиента в схеме `recipe_library`)
выполнен эвристиками и дал непригодные данные. Подтверждено запросами к живой
БД (контейнер `ration-db-1`, БД `ration`):

- **Ингредиенты склеены**: «`100 г сметаны морская соль в хлопьях и черный перец`»,
  «`Мука - 150 г Разрыхлитель - 1/2 ч. л`» — несколько продуктов в одной строке.
  959 из 6353 строк (15%) длиннее 60 символов, максимум — 5554 символа.
- **Шаги приготовления записаны как ингредиенты**: «`4. Для заправки смешать все
  ингредиенты…`» → quantity_min = 4.
- **Метаданные как ингредиенты**: «`2 ПОРЦИИ 10 МИНУТ • • •`».
- **Обрывки строк**: «`кокосовое) – 300-350 мл`» — начало названия потеряно.
- **35% ингредиентов без unit_code**; мусорные коды `чл`, `стл`; «по вкусу»
  закодировано магической строкой в `unit_code` вместо флага.
- **Битые названия рецептов**: «`SERVES 4 TO 6`», «`СЛАДОСТИ БЕЗ САХАРА
  67ПЕЧЕНЬЕ, ПИРОЖНЫЕ…`» (колонтитул), «`I L E Приготовленные овощи`»,
  mojibake CP1251 («`Áåëüêîâè÷…`»), «Рецепт без распознанного названия».
- **12 из 39 книг исключены целиком** («не найдены устойчивые границы рецептов»).
- **OCR ни разу не отработал**: 1169 страниц пустые, `pages_ocr = 0`.
- **0 рецептов в статусе `ready`** — планировщик работает на непроверенных данных.

## 2. Архитектура решения

```
PDF ──(1) PyMuPDF: текст с сохранением вёрстки──────▶ source_pages (v2)
    ──(2) чистка: колонтитулы, дубли глифов, mojibake─▶ чистые страницы
    ──(3) окна из 4 страниц (шаг 3)──────────────────▶ data/recipes/windows/*.md
    ──(4) СЕССИЯ CLAUDE CODE (Haiku, подписка)───────▶ data/recipes/extracted/*.json
         работает по промту ТЗ/PROMPT-HAIKU-RECIPES.md
    ──(5) загрузка: схема-валидация, дедуп, правила──▶ recipe_library (ready / needs_review)
```

Этапы 1–3 и 5 — код (команды CLI). Этап 4 — ручной запуск сессии Haiku
пользователем; она читает файлы-окна и пишет файлы-результаты. Обе стороны
устойчивы к прерыванию и повторному запуску.

**Поправка к TZ-v2 «LLM не входит в runtime»**: остаётся в силе для рантайма
(поиск, планировщик, web). LLM используется ТОЛЬКО на этапе offline-импорта
книг. Зафиксировать это предложение в `ТЗ/TZ-v2.md` («Зафиксированные решения»)
и в `ТЗ/README.md`.

### Этап 1 — извлечение текста (PyMuPDF)

- Зависимость: `pymupdf` (пакет PyPI `PyMuPDF`, `import fitz`). Добавить в
  `pyproject.toml` в extra `recipes` и в `Dockerfile.recipes`.
- Для каждой страницы: `page.get_text("dict")` → блоки → строки → спаны.
- Порядок чтения: кластеризовать блоки по центру `x`; если есть два кластера с
  зазором ≥ 40 pt — читать колонку за колонкой (левая сверху вниз, затем
  правая), иначе сверху вниз по `y0`.
- Внутри строки спаны соединять пробелом, строки — `\n`, блоки — `\n\n`.
  **НЕ схлопывать переводы строк** (антидефект D2).
- Если на странице < 40 алфавитно-цифровых символов и OCR включён — OCR через
  существующие `pdftoppm` + `tesseract`, но `RECIPE_OCR_DPI=300` (новое
  умолчание) и `--psm 4`. Починить причину `pages_ocr = 0`: в старом коде
  страницы получали метод `empty` — убедиться, что ветка OCR реально достижима,
  логировать каждый вызов событием `page_ocr`.
- Сохранять в `source_pages` с `extraction_method = 'pymupdf'` (или `'ocr'`).

### Этап 2 — чистка страниц

Модуль `app/recipes/cleaning.py` (чистые функции, покрыть тестами):

1. `dedupe_glyphs(line)` — псевдожирный дублирует фрагменты: если строка —
   конкатенация `s+s` (возможно с одним разделителем) — вернуть `s`; плюс
   схлопывание соседних одинаковых слов длиной ≥ 4
   («фиников фиников» → «фиников»).
2. `fix_mojibake(text)` — если в строке доля символов `[À-þ]` > 30%,
   попробовать `text.encode('latin-1').decode('cp1251')`; принять, если доля
   кириллицы выросла.
3. `strip_running_headers(pages)` — посчитать частоту нормализованных строк
   (lower, без цифр/пунктуации) по всем страницам книги; строки, встречающиеся
   на ≥ 15% страниц (и минимум на 5), удалить со всех страниц. Это убирает
   колонтитулы («Готовим в аэрогриле. ПП-меню», «СЛАДОСТИ БЕЗ САХАРА»).
4. `strip_page_numbers(page_text)` — одиночные строки-числа и строки вида
   `-НАЗВАНИЕ- 69` в начале/конце страницы.

### Этап 3 — окна-кандидаты (файлы для Haiku)

Модуль `app/recipes/windows.py` + команда CLI `export-windows`:

- Окно = 4 последовательные страницы книги, шаг 3 (одна страница перекрытия,
  чтобы рецепт, начавшийся в конце окна, целиком попал в следующее).
- Пропускать окна, где суммарно < 200 алфавитно-цифровых символов.
- `window_id = f"{source_id:03d}-{page_start:04d}-{page_end:04d}"`.
- Файл `data/recipes/windows/{window_id}.md` в формате:

```
---
window_id: 007-0042-0045
source_id: 7
source_title: 45 оттенков зеленого
pages: 42-45
sha256: <sha256 текста окна>
---
=== СТРАНИЦА 42 ===
<текст страницы>
=== СТРАНИЦА 43 ===
...
```

- Манифест `data/recipes/windows/manifest.json`: список всех окон
  (`window_id`, `source_id`, `pages`, `sha256`, `chars`). Повторный экспорт
  перезаписывает только изменившиеся окна (сравнение по sha256).
- Ожидаемый объём: ~8600 страниц → ~2900 окон. По подписке это бесплатно;
  сессия Haiku обрабатывает окна пачками и может быть перезапущена в любой
  момент (готовые результаты не переделываются).

### Этап 4 — распознавание сессией Haiku (вне кода)

Пользователь открывает НОВУЮ сессию Claude Code в каталоге проекта, выбирает
модель Haiku и даёт команду: «выполни ТЗ/PROMPT-HAIKU-RECIPES.md». Сессия:

- берёт из `data/recipes/windows/` окна, для которых нет результата в
  `data/recipes/extracted/`;
- для каждого окна извлекает рецепты по правилам промта и пишет файл
  `data/recipes/extracted/{window_id}.json` (схема — раздел 3);
- окна без рецептов тоже получают файл (`{"recipes": []}`) — это отметка
  «обработано»;
- работает до конца списка; при обрыве продолжает с места остановки.

Промт и схема лежат в `ТЗ/PROMPT-HAIKU-RECIPES.md` — этот файл создаёт
исполнитель настоящего ТЗ (задача T5) на основе раздела 3 и правил из
раздела 4. Промт уже написан — см. файл; при изменении схемы синхронизировать
оба места.

### Этап 5 — загрузка результатов

Команда CLI `load-extracted`:

1. Прочитать все `data/recipes/extracted/*.json`.
2. **Схема-валидация** каждого файла (без внешних зависимостей — ручная
   проверка типов по разделу 3; функция `validate_payload(dict) -> list[str]`
   возвращает список ошибок). Файлы с ошибками — в отчёт, окно считается
   необработанным.
3. Сохранить сырой ответ в таблицу `recipe_library.llm_extractions`
   (идемпотентно, PK по `window_sha256 + model + schema_version`).
4. **Дедупликация** между окнами: ключ `(source_id, normalize(title),
   page_start ± 1)`, где `normalize` = lower + без пунктуации + схлопнутые
   пробелы. При дубле предпочесть кандидата с `is_complete=true`, при
   равенстве — с большим числом ингредиентов.
5. **Правила готовности** (модуль `app/recipes/validate.py`): рецепт получает
   `review_status='ready'`, если ВСЕ условия выполнены, иначе `needs_review`
   со списком причин в новом поле `review_reasons`:
   - ≥ 2 ингредиентов и ≥ 1 шаг;
   - каждый ингредиент: name не пуст, длина ≤ 60, не содержит глаголов
     приготовления (нареж, смеша, взбе, обжар, вылож, запека, добав, перемеша,
     раздав, измельч) и (quantity_min задан ИЛИ is_to_taste=true);
   - у ≥ 80% количественных ингредиентов unit задан;
   - title: 3–120 символов, доля букв ≥ 60%, не начинается с цифры, не равен
     названию книги;
   - servings задан ИЛИ yield_text задан (причина `no_yield` — по TZ-M2 §6);
   - шаги: каждый ≥ 15 символов, суммарно ≥ 80.
   Кандидаты вовсе без ингредиентов или шагов — отбрасываются.
6. **Запись** — транзакционно через `replace_recipes` per source
   (`app/recipes/database.py:170`) с расширенными полями,
   `extraction_method='llm'`.

Кухню (`cuisine_code`) НЕ угадывать — по TZ-M2 «значение остаётся не
определена, а не угадывается». Оставлять NULL; эвристику `_cuisine` не
переносить.

## 3. Формат результата (contract с Haiku)

Файл `data/recipes/extracted/{window_id}.json`:

```json
{
  "window_id": "007-0042-0045",
  "sha256": "<sha256 из шапки окна>",
  "model": "haiku-session",
  "schema_version": 1,
  "recipes": [
    {
      "title": "Рис с бамией и вялеными томатами",
      "page_start": 42,
      "page_end": 43,
      "is_complete": true,
      "servings_min": 3,
      "servings_max": 4,
      "yield_text": "НА 3–4 ПОРЦИИ",
      "time_total_minutes": null,
      "meal_types": ["lunch", "dinner"],
      "diet_tags": ["vegan_claim"],
      "appliances": ["stove"],
      "ingredients": [
        {
          "raw_text": "1 стакан риса",
          "name": "рис",
          "quantity_min": 1,
          "quantity_max": 1,
          "unit": "glass",
          "is_to_taste": false,
          "section": null,
          "note": null
        },
        {
          "raw_text": "соль и молотый черный перец",
          "name": "соль",
          "quantity_min": null,
          "quantity_max": null,
          "unit": null,
          "is_to_taste": true,
          "section": null,
          "note": "и молотый чёрный перец — отдельным ингредиентом"
        }
      ],
      "steps": [
        "Нарезать лук, чеснок и перец чили.",
        "В сотейник влить масло, добавить овощи и тушить пять минут."
      ]
    }
  ]
}
```

Ограничения полей:

- `meal_types` ⊆ {breakfast, lunch, dinner, dessert, snack, drink};
- `diet_tags` ⊆ {vegan_claim, vegetarian_claim, sugar_free_claim, gluten_free_claim};
- `appliances` ⊆ {oven, stove, microwave, pressure_cooker, multicooker,
  air_fryer, electric_grill, grill, blender, mixer, food_processor, autoclave,
  steamer, fridge_freezer};
- `unit` ∈ {g, kg, mg, ml, l, piece, tablespoon, teaspoon, cup, glass, clove,
  bunch, can, package, pinch, slice, stalk, leaf, sprig, handful, drop} или null.
  `cup` (амер. ~240 мл) и `glass` (стакан ~200–250 мл) — разные единицы;
  пересчёт в граммы — задача M3.
- «по вкусу» — это `is_to_taste=true, unit=null`; больше НИКОГДА не
  `unit='to_taste'`.

## 4. Правила извлечения (дублируются в промте Haiku)

1. Извлекать только настоящие рецепты (название + ингредиенты + способ
   приготовления). Введения, советы, оглавления — не рецепты.
2. Извлекать только рецепты, чьё название находится на первых трёх страницах
   окна; начавшиеся на последней странице достанет следующее окно.
3. `title` — название блюда, обычный регистр, без колонтитулов и категорий.
4. **Каждый продукт — отдельный элемент**; склеенные строки разделять.
5. `name` — существительное без количества и обработки; обработку — в `note`.
6. Диапазоны «2–3» → min/max; дроби → десятичные; нет количества → null +
   `is_to_taste` по смыслу.
7. `section` — подзаголовок группы («для теста»), lower, без двоеточия.
8. `steps` — шаги без номеров; сплошной текст разбить на логические шаги.
9. Ничего не выдумывать: нет данных — null. Язык оригинала сохранять.
10. Ответ — строго JSON по схеме.

## 5. Изменения схемы БД

Добавить в конец `app/recipes/schema.sql`:

```sql
ALTER TABLE recipe_library.recipe_ingredients
    ADD COLUMN IF NOT EXISTS is_to_taste BOOLEAN NOT NULL DEFAULT FALSE,
    ADD COLUMN IF NOT EXISTS section TEXT,
    ADD COLUMN IF NOT EXISTS note TEXT;

ALTER TABLE recipe_library.recipes
    ADD COLUMN IF NOT EXISTS time_total_minutes INTEGER,
    ADD COLUMN IF NOT EXISTS extraction_method TEXT NOT NULL DEFAULT 'heuristic',
    ADD COLUMN IF NOT EXISTS review_reasons JSONB NOT NULL DEFAULT '[]'::jsonb;

CREATE TABLE IF NOT EXISTS recipe_library.llm_extractions (
    window_sha256 TEXT NOT NULL,
    model TEXT NOT NULL,
    schema_version INTEGER NOT NULL,
    source_id BIGINT NOT NULL REFERENCES recipe_library.sources(id) ON DELETE CASCADE,
    page_start INTEGER NOT NULL,
    page_end INTEGER NOT NULL,
    response JSONB NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (window_sha256, model, schema_version)
);
```

## 6. CLI

Расширить `app/recipes/cli.py` подкомандами:

- `export-windows [--only ТЕКСТ] [--max-books N] [--force]` — этапы 1–3.
  `--force` переизвлекает страницы; без него страницы с методом `pymupdf`
  не переизвлекаются. В конце печатает: окон всего / новых / без изменений.
- `extract-status` — прогресс этапа 4: окон всего, обработано (есть валидный
  .json), осталось, с ошибками схемы.
- `load-extracted [--only ТЕКСТ]` — этап 5. Идемпотентна: повторный запуск не
  меняет данные, если файлы не менялись.
- `summary` — дополнить: рецепты по `review_status` и `extraction_method`,
  средняя длина `ingredient_text`, счётчик `llm_extractions`.

Прогресс — теми же JSON-событиями `event(...)`, что и сейчас.

Docker: `docker compose --profile manual run --rm recipe-importer python -m
app.recipes.cli export-windows` должен работать (том `./data` уже смонтирован).
Сессия Haiku работает с файлами напрямую на хосте — Docker ей не нужен.
`load-extracted` требует доступ к БД: запускать так же через compose.

`.env.example` дополнить:

```
# Переимпорт рецептов: окна и загрузка результатов сессии Haiku
RECIPE_OCR_DPI=300
RECIPE_WINDOW_PAGES=4
RECIPE_WINDOW_STEP=3
RECIPE_LLM_SCHEMA_VERSION=1
```

`tests/test_recipe_cleaning.py`, `tests/test_recipe_windows.py`,
`tests/test_recipe_validate.py`, `tests/test_recipe_load.py` — unittest, без

- `validate_payload`: правильный JSON проходит; неверный enum у unit, лишнее

## 8. Критерии приёмки (SQL после полного цикла)

```sql
-- 1. Доля «длинных» ингредиентов < 2% (сейчас 15%)
SELECT count(*) FILTER (WHERE length(ingredient_text) > 60)::float / count(*)
FROM recipe_library.recipe_ingredients;                          -- < 0.02

-- 2. Количественные ингредиенты: без количества и без is_to_taste — < 5%
SELECT count(*) FILTER (WHERE quantity_min IS NULL AND NOT is_to_taste)::float / count(*)
FROM recipe_library.recipe_ingredients;                          -- < 0.05

-- 3. Шагов в ингредиентах почти нет (сейчас 274)
SELECT count(*) FROM recipe_library.recipe_ingredients
WHERE ingredient_text ~* '(нареж|смеша|взбе|обжар|вылож|запека|перемеша)';  -- < 30

-- 4. Названия: без цифр в начале и КАПС-мусора (сейчас 14 и 264)
SELECT count(*) FROM recipe_library.recipes
WHERE title ~ '^[0-9]' OR (title = upper(title) AND length(title) > 25);    -- < 10

-- 5. Есть готовые рецепты
SELECT count(*) FROM recipe_library.recipes WHERE review_status = 'ready';  -- >= 300

-- 6. Исключено меньше книг, чем раньше (сейчас 12)
SELECT count(*) FROM recipe_library.sources WHERE import_status = 'excluded'; -- <= 6

-- 7. Идемпотентность: повторный load-extracted не меняет счётчики
--    recipes / recipe_ingredients / recipe_steps.
```

Плюс ручная выборка: 30 случайных названий читаются как названия блюд; 30
случайных ингредиентов — по одному продукту на строку.

**Результаты приёмки (2026-08-16, все 2833 окна, 3130 рецептов, 988 ready):**
критерий 1 — 0.0000 (цель <0.02); критерий 2 — 0.0612 (цель <0.05, отклонение
принято: выборка показала, что это ингредиенты, у которых количества нет
в самой книге — «зелень для подачи», «дольки лимона», «по желанию»);
критерий 3 — 2 (цель <30); критерий 4 — 6 (цель <10); критерий 5 — 988
(цель ≥300); критерий 6 — 2 книги (цель ≤6); критерий 7 — повторный
`load-extracted` не меняет счётчики (3130 / 27411 / 22361). Ручные выборки
названий и ингредиентов пройдены.
