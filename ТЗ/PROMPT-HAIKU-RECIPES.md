# Промт для сессии Haiku: распознавание рецептов из окон

> Скопируй этот текст в новую сессию Claude Code (модель Haiku) в каталоге
> `F:\Cloud\Eda`, либо просто напиши ей: «выполни ТЗ/PROMPT-HAIKU-RECIPES.md».
> Требование: окна уже экспортированы командой `export-windows`
> (каталог `data/recipes/windows/` не пуст).

---

Ты — конвейер распознавания рецептов. Работай строго по этой инструкции, ничего
не придумывай сверх неё. Не редактируй никакие файлы проекта, кроме создания
JSON-файлов в `data/recipes/extracted/`.

## ЗАПРЕЩЕНО (главное правило)

**НЕ ПИШИ скрипты, парсеры или программы, которые извлекают рецепты из текста
(Python, регулярные выражения, эвристики — что угодно).** Такой парсер уже
существовал в проекте и именно он произвёл мусор, ради которого затеян
переимпорт. Извлекать рецепты должен ТЫ САМ: прочитай окно глазами, пойми
текст и выпиши JSON. Это и есть твоя работа; автоматизировать её кодом нельзя.

Скрипты/команды разрешены только для двух вещей:
1) получить список необработанных окон (сравнение имён файлов);
2) записать УЖЕ СОСТАВЛЕННЫЙ тобой JSON в файл.

Если ты поймал себя на мысли «напишу скрипт, это эффективнее» — остановись:
это прямое нарушение инструкции. Правильный ритм: прочитал окно → сам составил
JSON → записал файл → следующее окно.

**Также запрещено массово создавать файлы-«заглушки» с пустым `recipes` для
окон, которые ты не читал.** Пустой `recipes` разрешён только для окна,
которое ты прочитал в этом же ходу и убедился, что рецептов там нет.
Загрузчик автоматически отвергает пустые результаты для окон, похожих на
рецепты (маркеры «Ингредиенты», граммовки): такие файлы уйдут в карантин,
окна вернутся в очередь, и твоя «работа» окажется напрасной. Обмануть
загрузчик нельзя — честная обработка единственный путь к завершению задачи.

Скорость не важна. Важно качество. Никто не требует закончить всё за один
раз: сессию можно прерывать и перезапускать сколько угодно.

## Задача

В каталоге `data/recipes/windows/` лежат файлы `*.md` — фрагменты кулинарных
книг (4 страницы, разделённые маркерами `=== СТРАНИЦА N ===`), с YAML-шапкой
(`window_id`, `source_id`, `source_title`, `pages`, `sha256`). Текст извлечён из
PDF и может содержать артефакты: обрывы строк, остатки колонтитулов,
перепутанные колонки, опечатки OCR.

Для КАЖДОГО файла окна нужно создать файл результата
`data/recipes/extracted/{window_id}.json`. Если для окна такой файл уже
существует — окно пропускается (оно уже обработано).

## Процесс (повторяй, пока есть необработанные окна)

1. Получи список необработанных окон. Самый дешёвый способ — одной командой:
   сравнить имена файлов в `data/recipes/windows/*.md` и
   `data/recipes/extracted/*.json` (без расширений) и вывести первые 10
   отсутствующих.
2. Прочитай очередной файл окна целиком.
3. Извлеки рецепты по правилам ниже.
4. Запиши файл `data/recipes/extracted/{window_id}.json` (кодировка UTF-8).
   Если рецептов в окне нет — запиши `{"window_id": "...", "sha256": "...",
   "model": "haiku-session", "schema_version": 1, "recipes": []}` — это отметка
   «обработано».
5. Перед записью выполни самопроверку (раздел «Самопроверка»).
6. Обрабатывай окна пачками по 10, затем коротко отчитайся одной строкой:
   «обработано N окон, осталось M» — и продолжай без вопросов, пока окна не
   закончатся. Не спрашивай разрешения продолжать.
7. Если файл окна повреждён или нечитаем — создай результат с пустым `recipes`
   и полем `"error": "<одно предложение>"`, продолжай со следующим окном.

## Формат результата (строго)

```json
{
  "window_id": "007-0042-0045",
  "sha256": "<скопируй из YAML-шапки окна>",
  "model": "haiku-session",
  "schema_version": 1,
  "recipes": [
    {
      "title": "Рис с бамией и вялеными томатами",
      "page_start": 42,
      "page_end": 43,
      "is_complete": true,
      "servings_min": 3,
      "servings_max": 4,
      "yield_text": "НА 3–4 ПОРЦИИ",
      "time_total_minutes": null,
      "meal_types": ["lunch", "dinner"],
      "diet_tags": [],
      "appliances": ["stove"],
      "ingredients": [
        {
          "raw_text": "1 стакан риса",
          "name": "рис",
          "quantity_min": 1,
          "quantity_max": 1,
          "unit": "glass",
          "is_to_taste": false,
          "section": null,
          "note": null
        }
      ],
      "steps": [
        "Нарезать лук, чеснок и перец чили.",
        "В сотейник влить масло, добавить овощи и тушить пять минут."
      ]
    }
  ]
}
```

Допустимые значения (НИКАКИХ других):

- `meal_types`: breakfast, lunch, dinner, dessert, snack, drink
- `diet_tags`: vegan_claim, vegetarian_claim, sugar_free_claim, gluten_free_claim
- `appliances`: oven, stove, microwave, pressure_cooker, multicooker, air_fryer,
  electric_grill, grill, blender, mixer, food_processor, autoclave, steamer,
  fridge_freezer
- `unit`: g, kg, mg, ml, l, piece, tablespoon, teaspoon, cup, glass, clove,
  bunch, can, package, pinch, slice, stalk, leaf, sprig, handful, drop — или null
- Числа — числа (не строки). Отсутствующее значение — null, не пустая строка.

## Правила извлечения

1. **Что считать рецептом.** Название + список продуктов + способ приготовления.
   Введения, советы, описания продуктов, оглавления, меню — НЕ рецепты.
   Если в окне рецептов нет — пустой массив `recipes`.
2. **Какие рецепты брать.** Только те, чьё НАЗВАНИЕ находится на первых трёх
   страницах окна. Рецепт, начавшийся на последней (четвёртой) странице, не
   бери — его целиком возьмёт следующее окно. Если конец рецепта обрезан
   окном — всё равно верни его с тем, что видно, и `is_complete: false`.
3. **title.** Настоящее название блюда. Убери колонтитулы, номера страниц,
   названия разделов («Завтраки», «Супы»), имя книги. СПЛОШНЫЕ ЗАГЛАВНЫЕ
   переведи в обычный регистр с заглавной первой буквой. Исправь очевидные
   артефакты («ПУ ДИНГ» → «Пудинг», «С Л А Д О С Т И» → «Сладости»).
4. **Каждый продукт — отдельный элемент массива ingredients.** В исходнике
   продукты часто склеены в одну строку. Примеры разделения:
   - «Мука - 150 г Разрыхлитель - 1/2 ч. л» → два элемента: мука 150 g и
     разрыхлитель 0.5 teaspoon;
   - «100 г сметаны морская соль в хлопьях и черный перец» → три элемента:
     сметана 100 g; соль морская is_to_taste; перец чёрный is_to_taste;
   - «соль и перец по вкусу» → два элемента, оба is_to_taste.
   `raw_text` каждого элемента — точный кусок исходной строки про этот продукт.
5. **name** — только продукт: «мука», «сметана», «чеснок». Нижний регистр,
   именительный падеж, единственное число. Способ обработки («мелко нарезать»,
   «очистить», «комнатной температуры») — в `note`, не в name.
6. **Количества.** «2–3 зубчика» → quantity_min 2, quantity_max 3.
   «150 г» → 150 и 150. Дроби в десятичные: 1/2 → 0.5, 1½ → 1.5, ¼ → 0.25.
   Нет количества → оба null; если по смыслу «по вкусу»/«для подачи»/«щепотка
   без числа» → is_to_taste: true.
7. **Единицы.** «ст. л.», «ст. ложка», «столовая ложка», «tbsp» → tablespoon.
   «ч. л.», «чайная ложка», «tsp» → teaspoon. «стакан» → glass. «чашка», «cup»
   → cup. «шт», «штука» → piece. «зубчик» → clove. «пучок» → bunch. «банка» →
   can. «упаковка», «пачка» → package. «щепотка» → pinch. «ломтик» → slice.
   «стебель» → stalk. «лист» → leaf. «веточка» → sprig. «горсть» → handful.
   «капля» → drop. «г», «гр», «грамм» → g. «кг» → kg. «мл» → ml. «л» → l.
   Если единицы нет в списке (например «формочка») → unit: null, единицу
   оставь в raw_text/note.
8. **section** — подзаголовок группы продуктов, если он есть в исходнике
   («ДЛЯ САЛАТА», «Для крема:») → «для салата», «для крема» (нижний регистр,
   без двоеточия) у всех продуктов этой группы. Нет групп — null.
9. **steps** — шаги приготовления по порядку, без номеров в начале текста.
   Если способ приготовления — сплошной текст, разбей его на логические шаги
   (одно-три предложения на шаг). В шаги не включай ингредиенты, колонтитулы,
   советы «на заметку» и истории автора.
10. **Ничего не выдумывай.** Нет порций — servings null. Нет времени —
    time_total_minutes null. Не переводи текст: английский рецепт остаётся
    английским (правила name/unit те же: «flour» → name «flour»).
11. **appliances** — только техника, реально требуемая шагами (духовка → oven,
    сковорода/кастрюля/плита → stove, блендер → blender...). Ничего не нужно —
    пустой массив.
12. **meal_types/diet_tags** — только если это очевидно из текста или раздела
    книги (страница «ЗАВТРАКИ» → breakfast; «веганский» → vegan_claim). Не
    уверен — пустой массив.

## Самопроверка перед записью файла

- JSON валиден и содержит все обязательные поля (`window_id`, `sha256`,
  `model`, `schema_version`, `recipes`).
- Ни один `ingredients[].name` не длиннее 60 символов и не содержит глаголов
  (нарезать, смешать, взбить, обжарить, выложить, запекать, добавить).
  Если содержит — ты не разделил строку: исправь.
- Ни один элемент `steps` не выглядит как строка ингредиента («200 г муки»).
- Все enum-значения из допустимых списков; числа — числами; null — null.
- `page_start` — реальный номер из маркера `=== СТРАНИЦА N ===`.

## Завершение

Когда необработанных окон не останется, выведи итог: сколько окон обработано,
сколько рецептов извлечено, сколько окон с `error`. После этого пользователь
запустит загрузку в базу командой:
`docker compose --profile manual run --rm recipe-importer python -m app.recipes.cli load-extracted`
