# Аудит проекта «Рацион» — 16.08.2026

Полное код-ревью: три параллельных обзора кода (импорт рецептов, веб-приложение,
инфраструктура/ТЗ) + прямые запросы к живой БД `ration-db-1`. Здесь собраны ВСЕ
найденные ошибки. Что чинить и как — в профильных ТЗ:
[TZ-M2R](TZ-M2R-RECIPES-LLM.md) (рецепты), [TZ-M6R](TZ-M6R-UI-REDESIGN.md)
(интерфейс + баги бэкенда), [TZ-M5R](TZ-M5R-PLANNER.md) (планировщик),
[TZ-TESTS](TZ-TESTS.md) (тесты).

## 1. Данные рецептов (критично)

Все 787 рецептов `needs_review`, 0 `ready`. 15% ингредиентов — склеенные блобы
(до 5554 символов), 274 строки-ингредиента содержат глаголы приготовления
(это шаги), 35% без единицы измерения, названия — колонтитулы и mojibake,
12 из 39 книг исключены, OCR не отработал ни разу (1169 пустых страниц).
Корневые дефекты парсера — 14 штук, разобраны в TZ-M2R §1 (D1–D14) с точными
file:line. Вывод: данные пересоздаются заново конвейером TZ-M2R, старый
`app/recipes/parsing.py` удаляется.

## 2. Веб-бэкенд: баги (`app/web/`)

### Высокая важность

| # | Баг | Место |
|---|-----|-------|
| B1 | **План «исчезает» после перезагрузки.** `latest_plan` возвращает `None`, если ХОТЯ БЫ ОДНО название блюда не проходит `is_dish_title` по сырому title, хотя при генерации проверялся очищенный. Пользователь создаёт меню, обновляет страницу — меню пропало без сообщения. | `app/web/database.py:685-686`, `app/web/planner.py:330` |
| B2 | **Новый пользователь заблокирован.** Регистрация создаёт 0 единиц техники, а `_recipe_allowed` требует `required ⊆ appliances` — проходят только рецепты с пустым списком техники; чаще всего планировщик падает с «осталось слишком мало рецептов» (тост на 3 секунды без объяснения). | `app/web/planner.py:342,704-705`, `app/web/database.py:91-98` |
| B3 | **`target_kcal` собирается и нигде не используется.** UI, схема и payload несут цель калорий, `build_plan` читает только `portion_factor`. | `app/web/planner.py:708`, `schema.sql:52` |

### Безопасность (локальный хост смягчает, но чинить)

| # | Баг | Место |
|---|-----|-------|
| S1 | CSRF-токен сравнивается `==`, не constant-time. Использовать `secrets.compare_digest`. | `database.py:172` |
| S2 | Нет rate-limit на `/api/auth/login`; Argon2 19 MiB × параллельные запросы = DoS-вектор. | `main.py:148` |
| S3 | `logout` требует CSRF: потеряв CSRF-cookie, нельзя отозвать сессию из UI. | `main.py:158-161` |
| S4 | Нет security-заголовков (CSP, X-Content-Type-Options, X-Frame-Options) при 17 innerHTML-рендерах с ручным экранированием. | `main.py:46-51` |
| S5 | `recipe_detail` отдаёт `r.*` — наружу утекают `source_id`, `fingerprint` (README обещает не раскрывать источники). | `database.py:363,432` |
| S6 | `delete_inventory` проверяет успех через `result.endswith("1")` — «DELETE 11» тоже «успех». Парсить счётчик. | `database.py:538` |
| S7 | Сессия жёстко привязывается к первому household (`ORDER BY created_at LIMIT 1`) — мультисемейность невозможна. | `database.py:142-148` |
| S8 | `add_inventory` принимает `expires_on` в прошлом без валидации — портит сортировку FEFO. | `main.py:243-250` |

### Фронтенд (сводно; детально — TZ-M6R)

- styles.css: 18 КБ в 16 физических строках (строки до 3093 символов) —
  неподдерживаемо; app.js — строки до 1961 символа; 17 innerHTML-рендеров
  строковой конкатенацией; обработчики переназначаются после каждого рендера.
- Роутинга нет (Back не работает), состояний загрузки/пустоты почти нет,
  ошибки — исчезающий тост с сырым `detail`.
- Шрифт Inter объявлен, но не подключён; font-weight 750/850 не работают без
  variable-шрифта; 8 разных радиусов скругления; контраст `.eyebrow` ниже 4.5:1.
- Список рецептов не показывает ни одного ингредиента (бэкенд отбрасывает
  `ingredient_names` в `database.py:345`); карточка «нужна проверка» у 100%.
- Доминирующий паттерн — факты через « · » в одном `<small>` (запасы, покупки) —
  и есть «нераздельность», на которую жалуется пользователь.
- Настройки — lossy round-trip: типы правил и `is_hard` схлопываются при
  каждом сохранении; люди пересоздаются с новыми UUID.
- Нет: пагинации, истории планов, замены блюда, отметки «куплено», управления
  review_status, тёмной темы; удаление через native confirm().

## 3. Несоответствия TZ-v2 / TZ-M1 / TZ-M2

- **M5-оптимизатор**: OR-Tools CP-SAT (минимизация стоимости + порчи) не
  существует; вместо него ручная эвристика в `planner.py`.
- **M7 Telegram**: aiogram отсутствует, бота нет (только заготовки токенов).
- **Стек**: SQLAlchemy/Alembic нет — миграции через `CREATE TABLE IF NOT
  EXISTS` + ALTER-заплатки без истории версий.
- **Поиск**: PostgreSQL FTS / pg_trgm / словари синонимов (обязательные по
  TZ-v2 §3) — ноль вхождений в коде.
- **M3**: справочника КБЖУ/сроков хранения/коэффициентов съедобной части нет;
  `recipe_nutrition` нет.
- **TZ-M2 §3**: нет `recipe_raw_blocks` (координаты), `cuisines`/`recipe_cuisines`,
  `meal_types`-таблиц, `recipe_reviews`; кухня — одно текстовое поле и
  УГАДЫВАЕТСЯ вопреки прямому запрету («ИСПАНСКИЙ ОМЛЕТ» → italian, «63Супы
  Сезон» → russian).
- **TZ-M1**: нет `household_invites`, `inventory_events`, `meal_plan_versions`,
  `shopping_runs`, `telegram_dialog_state` — обещанная обратимая история
  изменений не обеспечена таблицами.
- **Лента**: `store_products.image_url` существует вопреки правилу «изображения
  не сохраняются»; детальные карточки загружены на 2.7% (321 с ккал из 12936);
  история цен — 2 дня (критерий истории акций не проверен).
- Порядок вех нарушен: M6 (web) построен до валидных данных M2/M3 — поэтому
  приложение работает на `needs_review`-рецептах и 35 правилах калорийности.

## 4. Инфраструктура и гигиена

- **~430 МБ реверс-инжиниринговых артефактов в `data/lenta/`**: полный APK
  (211 МБ), дистрибутив jadx с JRE (88 МБ + распакованный), dex-файлы,
  jadx-кэши. Вынести из проекта или удалить (контракт API уже зафиксирован в
  коде и `.env`).
- `data/browser-profile/` — мёртвый профиль Chromium от отброшенного
  Playwright-подхода; `data/diagnostics/` — скриншоты мёртвого пути. Удалить.
- `catalog-*.jsonl` содержит пустой файл 0 байт (артефакт упавшего прогона).
- Проект НЕ git-репозиторий; `.gitignore` есть, но не покрывает `Книги/`
  (900 МБ PDF с авторскими правами) и `tmp/` — при `git init` они попадут в
  индекс. Дополнить .gitignore до инициализации.
- Bind-mount `./книги:/app/books` (нижний регистр) работает только благодаря
  регистронезависимой ФС Windows; на Linux сломается — привести к `./Книги`.
- `docker-compose.yml`: у `web` нет volume для `static/` — каждая правка
  CSS/JS требует rebuild (отсюда ручные `?v=...` кэш-бастеры).
- Контейнеры-зомби от старых прогонов (`ration-lenta-full-20260814` exit 143 и
  др.) — вычистить `docker compose rm`.
- `.env` отсутствует (всё на дефолтах из `.env.example`) — завести реальный
  `.env`, хотя бы ради паролей БД.
