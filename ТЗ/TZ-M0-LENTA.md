# ТЗ M0 — сборщик каталога «Ленты»

## Цель

Один раз в сутки собирать продовольственный ассортимент «Гипер Ленты» №155 по
адресу Иваново, ул. Карла Маркса, 3 и сохранять цены, акции, фасовки и
доступность для дальнейшего расчёта меню и закупки.

## Подтверждённый источник

Основной адаптер использует гостевой API актуального официального Android-клиента:

- `GET /auth/session/guest/token` — гостевая сессия;
- `GET /stores/155` — проверка адреса и получение внутреннего ID `3269`;
- `PUT /stores/pickup/3269?autodetection=false` — выбор магазина;
- `POST /catalog/items` — список с `categoryId`, `limit`, `offset`;
- `GET /catalog/items/{id}` — состав, КБЖУ и характеристики.

Базовый адрес и версия клиентских заголовков вынесены в окружение, потому что
внутренний контракт может измениться вместе с приложением. При смене версии
сначала проверяется новый официальный APK, затем тестовые фикстуры и короткий
проход. Сборщик использует только гостевую сессию, ограничивает частоту запросов
и не обходит CAPTCHA, авторизацию или защиту сайта.

Web-каталог через Chromium проверен как резерв диагностики, но Qrator не
пропускает контейнер стабильно. Playwright и браузер не входят в рабочий образ.

## Охват

Корневые категории: алкоголь, готовая еда, овощи/фрукты, рыба/морепродукты,
мясо/птица, молоко/яйца, колбасы, сыры, заморозка, бакалея, хлеб, кофе/чай,
масла/соусы/специи, вода/напитки, сладости, консервация, снеки, здоровое и
детское питание. Один внешний ID может относиться к нескольким категориям, но
товар и ежедневная цена сохраняются без дублей.

Изображения, видео и отзывы не загружаются и не записываются даже в сырой JSON.

## Поля товара и цены

- внешний ID, название, URL и категории;
- исходная фасовка, нормализованное количество и единица (`g`, `ml`, `piece`);
- единица продажи;
- обычная цена, цена по Карте №1, акционная и персональная цена отдельными
  полями в целых копейках;
- процент скидки, лимит продажи и доступность (`count > 0`, продажа не заблокирована);
- бренд, артикул, состав, КБЖУ, условия и опубликованный срок хранения;
- время наблюдения и исходный JSON без медиа.

Без авторизации персональная цена остаётся `NULL`. Массовые скидки сохраняются в
сыром блоке цен до добавления отдельной нормализованной модели ценовых ступеней.

## Пагинация и обновления

- API сообщает `total`; страницы читаются по `limit/offset` до полного `total`;
- стандартный размер страницы — 40, задержка — 250 мс, оба параметра настраиваются;
- 429 и временные 5xx повторяются с ограниченным backoff;
- 401/403 один раз обновляет гостевую сессию;
- товар помечается недоступным из-за отсутствия в новом снимке только после
  полностью успешного прохода всех стандартных категорий;
- детали догружаются партиями (`LENTA_DETAIL_LIMIT`), сначала ещё не заполненные,
  затем самые старые;
- каждую категорию, страницу и прогресс деталей видно в JSON-логе.

## Хранение

Новая схема PostgreSQL называется `lenta_store`, чтобы не пересекаться со
старыми таблицами проекта. Основные таблицы: `stores`, `store_products`,
`store_product_categories`, `store_listings`, `store_price_history`,
`collection_runs`. Дополнительно каждый проход создаёт JSONL в `data/lenta/`.

Повторный запуск в тот же день обновляет наблюдение. Старые тома и таблицы не
удаляются автоматически.

## Режимы

- разовый: `docker compose --profile manual run --rm collector`;
- диагностика: параметры `--category`, `--max-pages`, `--detail-limit`;
- ночной: сервис `scheduler`, по умолчанию 03:00 `Europe/Moscow`.

## Критерии готовности

- точный магазин проверяется по полному адресу до записи цен;
- контрольный проход возвращает 40 товаров, сохраняет фасовки и обе публичные
  цены, а три детальные карточки — состав и КБЖУ;
- полный проход получает не менее 90% доступного ассортимента без дублей;
- не менее 85% карточек имеют нормализованную фасовку;
- частичная категория не делает отсутствующие товары недоступными;
- ежедневная история показывает смену обычной/карточной/акционной цены;
- модуль и расписание полностью запускаются через Docker Compose.
