> реализуемо всё, кроме §5.6 и §5.10 — тогда эти экраны делаются на нынешних
> полях (`price_tier`, без `reasons`).

> **Для исполнителя (сессия Claude Code на Opus).** Самодостаточное ТЗ.
> Текущий бот «Супостат» (@SoupoStatBot): `app/telegram/bot.py` (296 строк,
> свой транспорт на `httpx`, long polling) и `app/telegram/service.py`

> `tests/fakes.py`. Все ссылки на строки — на состояние репозитория 28.08.2026.

## 0. Цель

Всё, что можно сделать в web-приложении, можно сделать из бота — от
регистрации до замены блюда — не открывая браузер. Бот не «урезанный
клиент», а равноправный канал: один аккаунт, одна семья, одна история
(TZ-M1). Плюс то, что умеет только мессенджер: напоминания и утреннее меню.

Принцип: **веб и бот вызывают один и тот же слой данных** (`AppRepository`),
бот не ходит по HTTP в веб. Логика бота остаётся чистыми функциями без сети
(как сейчас в `service.py`), транспорт — отдельно.

## 1. Что есть и чего нет (по коду 28.08.2026)

«Неделя» текстом без кнопок, «Покупки» чек-листом (до 90 кнопок), карточку
рецепта, замену блюда (3 альтернативы, хотя веб даёт 10 —

(`database.py:1419`); ошибки Bot API нечитаемы (`raise_for_status` без
`description`, REPORT-2026-08-18 §4); плейсхолдер «⏳» может зависнуть навсегда.

## 2. Архитектура

```
Telegram ──long polling──▶ bot.py (транспорт: httpx, очередь update'ов)
                              │
                              ▼
                         router.py     команда / текст / callback → сцена
                              │
             ┌────────────────┼──────────────────┐
             ▼                ▼                  ▼
        scenes/*.py       fsm.py            render.py
   (чистые функции:    (состояние диалога   (тексты, клавиатуры,
    вход → Reply)      в БД, шаги, отмена)   пагинация, ≤4096 симв.)
             │
             ▼
     AppRepository (app/web/database.py) — тот же, что у веба
```

Решение по фреймворку: **остаёмся на своём транспорте**, не переходим на
aiogram. Причина: транспорт уже написан и покрыт тестами, а нужный нам FSM —
это 150 строк над таблицей `telegram_dialog_state` (предусмотрена TZ-M1).
Переход на aiogram дал бы готовый FSM, но потребовал бы переписать 38 тестов
и перенести всю логику; выигрыш не окупается. Если объём сцен вырастет
кратно — пересмотреть.

Новые файлы `app/telegram/`:

| Файл | Ответственность |
|---|---|
| `router.py` | разбор входящего update: команда, кнопка меню, callback, свободный текст → вызов сцены; проверка доступа и роли; rate limit |
| `fsm.py` | `DialogState(scene, step, data, updated_at)`; `load/save/clear`; таймаут 30 мин; универсальная «✖ Отмена» |
| `render.py` | форматтеры (переезд из `service.py:232-340`), пагинация, `chunk_buttons`, `split_for_telegram`, единый стиль эмодзи |
| `callbacks.py` | кодек `encode/parse` (переезд из `service.py:63-89`) с расширенным набором глаголов (§4) |
| `scenes/auth.py` | `/start`, регистрация, вход по коду для веба, отвязка |
| `scenes/plan.py` | мастер «Составить меню», просмотр плана по дням, замена, история |
| `scenes/shopping.py` | покупки по категориям, страницы, «есть дома» |
| `scenes/recipes.py` | поиск и фильтры, карточка, оценка, статус проверки |
| `scenes/inventory.py` | запасы: список, добавление с разбором строки, удаление |
| `scenes/products.py` | каталог Ленты |
| `scenes/settings.py` | семья, люди, техника, правила, профиль планирования, Telegram |
| `scenes/taste.py` | онбординг вкуса и сводка (M8 §4.4) |
| `notifications.py` | утреннее меню, вечернее «приготовили?», сроки годности, напоминание о покупках |
| `service.py` | остаётся как фасад совместимости на время миграции; после T9 удаляется |

Общий слой валидации: `PersonPayload`, `RulePayload`, `SettingsPayload`,
`PlanPayload`, `InventoryPayload` из `main.py:75-126` переезжают в
`app/web/payloads.py` и используются ботом — одни и те же правила
(логин `^[a-zA-Zа-яА-ЯёЁ0-9_.-]{3,40}$`, пароль 8–200, ккал 500–6000,
порция 0.1–3, дни 1–14 и т.д.), одни и те же тексты ошибок.

## 3. Доступ и безопасность

### 3.1 Личность

- Привязка и все проверки — по **Telegram `from.id`** (`user_id`), не по
  `chat_id`. `auth_identities.provider_user_id` хранит `from.id`;
  миграция: существующие строки с `chat_id` личных чатов совпадают с
  `from.id` (в личке они равны), остальные помечаются `needs_relink`.
- Бот работает **только в личных чатах** (`chat.type == 'private'`); в
  группе отвечает одной фразой «Я работаю только в личных сообщениях» и
  игнорирует остальное. Групповой режим не входит (§9).
- `context_for_chat` (`service.py:140`) → `context_for_user(from_id)`:
  пользователь, активная семья (`household_memberships`, поле
  `active_household_id` на `users` — добавить, дефолт первое членство), роль.
  Каждая сцена проверяет роль так же, как веб: `viewer` не пишет,
  `owner/admin` управляют настройками (`PermissionError` → «Нет прав»).

### 3.2 Регистрация из бота

`/start` без токена и без привязки:

```
Привет! Я «Супостат» — планирую меню семьи.
[ Создать аккаунт ]  [ У меня уже есть аккаунт ]
```

- **Создать аккаунт** → сцена `auth.register`: спросить название семьи
  (дефолт «Моя семья», кнопка «Так и оставить») → `AppRepository.register`
  (`database.py:132`) с логином `tg<from_id>` и **без пароля**
  (`password_credentials` не создаётся; `users.login` уникален) → сразу
  привязка `auth_identities` → онбординг вкуса (M8) или «Составить меню».
  Один `from.id` — один аккаунт (UNIQUE уже есть).
- **У меня уже есть аккаунт** → инструкция: в вебе «Настройки → Телеграм →
  Получить команду», ввести команду сюда; либо ссылка `deep_link`, если
  `TELEGRAM_BOT_USERNAME` задан. Механика `link_<token>` не меняется.

### 3.3 Вход в веб из бота (обратная привязка)

Аккаунт, созданный в боте, не имеет пароля. Команда `/web` (и кнопка в
«Настройки → Телеграм»):

1. бот создаёт `one_time_tokens(purpose='web_login', ttl=5 мин)`;
2. отвечает ссылкой `http://<WEB_PUBLIC_URL>/#/login/tg/<token>` и 6-значным
   кодом для ручного ввода на экране входа (вкладка «Войти через Telegram»);
3. веб: `POST /api/auth/telegram-login {token}` → проверка, `used_at`,
   `create_session` (`database.py:188`) → cookies как при обычном входе.
4. в вебе «Настройки → Аккаунт» появляется «Задать пароль» для входа без
   Telegram (`POST /api/auth/set-password`, требует активной сессии).

`WEB_PUBLIC_URL` — новая переменная у `bot` (дефолт `http://localhost:8080`).

### 3.4 Отвязка и выход

- `/unlink` и кнопка «Отвязать Telegram» (настройки, веб и бот): удаление
  строки `auth_identities`, очистка `telegram_dialog_state`, подтверждение
  «Да, отвязать». Для аккаунта без пароля — предупреждение «Вы не сможете
  войти без Telegram. Сначала задайте пароль (/web → Настройки)»; отвязка всё
  равно разрешена (владелец данных — пользователь).
- Веб получает `DELETE /api/telegram/link` (сейчас отвязки нет нигде).
- «Выход» в боте не нужен: сессии у бота нет; смена аккаунта = отвязка +
  новая привязка.

### 3.5 Лимиты и журнал

- rate limit в `router.py` на `from.id`: 20 сообщений/мин и 60
  callback/мин (тот же `ratelimit.py`); тяжёлые операции (генерация, замена)
  — не чаще 1 за 10 с и не более 1 одновременно на пользователя (нынешний
  `in_flight`, `bot.py:155`, расширить на сцены);
- `audit_log.channel='telegram'` во всех вызовах из бота: `_audit`
  (`database.py:1419`) получает параметр `channel`, псевдосессия бота
  (`service.py:521`) несёт `channel`;
- тексты сообщений не хранятся (TZ-M1); в `telegram_dialog_state.data`
  живут только поля текущей формы, `clear` при завершении/отмене/таймауте;
- секреты: `TELEGRAM_BOT_TOKEN` только у `bot`; `WEB_PUBLIC_URL` и
  `TELEGRAM_BOT_USERNAME` — у обоих.

## 4. Интерфейсные соглашения

### 4.1 Главное меню (reply-клавиатура)

```
🍽 Сегодня      📅 Меню
🛒 Покупки      🧊 Запасы
📖 Рецепты      ⚙️ Настройки
```

Плюс команды (`setMyCommands` при старте): `/start /menu /today /plan /new
/shopping /inventory /recipes /products /settings /taste /web /unlink /help
/cancel`.

### 4.2 Сцены и шаги

Любой многошаговый ввод — сцена в `fsm.py`: `scene`, `step`, `data`.
Правила:

- каждый шаг показывает, что уже введено, и inline-кнопки быстрых значений
  (даты «Сегодня / Завтра / Понедельник», дни «3 / 5 / 7 / 14», бюджет
  «3000 / 5000 / без бюджета»); свободный текст принимается всегда;
- «✖ Отмена» есть на каждом шаге и в `/cancel`; таймаут 30 минут —
  состояние очищается, следующее сообщение обрабатывается как новое;
- ошибка валидации — тем же текстом, что и веб (`payloads.py`), шаг
  повторяется;
- финальный шаг — сводка и «✅ Подтвердить».

### 4.3 Callback-кодек

`callbacks.py`: формат `<verb>:<args>` ≤ 64 байт, UUID — 22 символа
base64url (как сейчас). Глаголы:

| Глагол | Назначение | Аргументы |
|---|---|---|
| `s` | тумблер «куплено» | item_id |
| `r` | карточка рецепта | recipe_id, [plan_id] |
| `x` / `v` / `c` | замена: подобрать / применить / отмена | meal_id, recipe_id |
| `d` | показать день плана | plan_id, day_index |
| `p` | страница списка | scope (sh/rc/in/pr/pl), cursor |
| `k` | отметка блюда cooked/skipped | meal_id, status |
| `g` | оценка | recipe_id, 1–5 / 0 |
| `w` | статус проверки | recipe_id, ready/rejected/needs_review |
| `i` | запасы: удалить / подтвердить просрочку | lot_id |
| `f` | фильтр списка | scope, поле, значение |
| `o` | переключатель в настройках (техника, «ест дома», кухни) | код |
| `n` | навигация по сценам/подменю | scene, step |
| `t` | онбординг вкуса | recipe_id, like/skip/pass |
| `y` | подтверждение опасного действия | action, id |

Устаревшие кнопки (план/позиция не найдены) → `show_alert` «Кнопка
устарела, откройте заново» (как сейчас `STALE_TEXT`).

### 4.4 Длинные списки

`render.py:paginate(items, page, per_page)` — страницы по 8 позиций для
карточек и по 30 кнопок для чек-листов; навигация «◀ 2/5 ▶». Лимит 100
inline-кнопок и 4096 символов соблюдаются конструктивно, а не обрезанием.

### 4.5 Ошибки Bot API

`TelegramClient` (`bot.py:45`) логирует `description` из тела при любом
не-2xx; `edit_message_text` при 400 «message is not modified» — игнор,
при прочих 400 — отправка нового сообщения вместо правки. Плейсхолдер
«⏳…» отправляется **без** reply-клавиатуры (причина зависания из
REPORT-2026-08-18 §4).

## 5. Карта функций: веб → бот

Каждая строка — обязательство. Колонка «Веб» — что повторяем; «Бот» — как.

### 5.1 Аккаунт

| Веб | Бот |
|---|---|
| Регистрация (логин, пароль, семья) | §3.2: аккаунт без пароля, семья — один вопрос |
| Вход | привязка `link_<token>`; вход в веб — `/web` (§3.3) |
| Выход / отзыв сессий | `/unlink` (§3.4) |
| `GET /api/me` | «⚙️ Настройки» — шапка: логин, семья, роль |

### 5.2 Сегодня (дашборд)

| Веб | Бот |
|---|---|
| Ближайшие приёмы пищи | «🍽 Сегодня»: блюда дня с ккал/БЖУ и **причинами** (M8 §5) одной строкой; кнопки 📖 / 🔁 / ✅ Приготовили / ⏭ Пропустили (для прошедших слотов) |
| «Использовать скорее» (срок ≤ 3 дней) | блок внизу «Сегодня» + отдельное напоминание (§6) |
| Счётчики рецептов/запасов | «⚙️ Настройки → Данные» |

### 5.3 План: составить

Сцена `plan.new` (`/new`, кнопка «➕ Составить меню» в «📅 Меню»):

1. **С какого дня** — Сегодня / Завтра / Понедельник / ввести дату;
2. **Сколько дней** — 3 / 5 / 7 / 14 (дефолт из профиля);
3. **Бюджет** — из профиля / 3000 / 5000 / без бюджета / число;
4. **Режим** — Сбалансированно / Экономно / Разнообразие / Спорт / Быстро
   (M8) — либо Экономно / Сбалансированно / Премиально до M8;
5. **Кухни** — мультивыбор чипами через `o:`, «Как обычно» = из профиля;
6. **Сводка** → «✅ Составить» → фон (`_run_heavy`, `bot.py:222`) с
   плейсхолдером «⏳ Собираем меню… обычно 10–20 секунд»; по готовности —
   день 1 плана с навигацией по дням + строка «Бюджет: 4 120 ₽ из 5 000;
   покрытие каталогом 92 %; предупреждения: 2» и кнопка «🛒 Покупки».

Ошибки: 422 «нет подходящих рецептов» → текст и кнопка «Изменить
параметры» (возврат к шагу 5); `not_enough_recipes` в слотах — показывать
слот «— пусто —» с причиной.

### 5.4 План: просмотр и история

| Веб | Бот |
|---|---|
| План по дням, слоты, ккал/БЖУ, бейджи предупреждений | «📅 Меню»: активный план, день за днём через `d:`; бейджи текстом: «черновик», «порции как в книге», «кухня не совпала», «ккал частично», «на два раза» |
| Кнопки на любой день | 📖 / 🔁 / ✅ / ⏭ на каждом блюде каждого дня (сейчас — только «Сегодня») |
| История планов (20) | «📅 Меню → 🗂 История»: страницы по 8, «дата · дней · сумма», открытие делает план **активным для бота** (`telegram_dialog_state.data.active_plan_id`; по умолчанию — последний) |
| Удаление плана | «🗑 Удалить» → `y:` подтверждение |
| Сводка: сопоставлено X из Y, покрытие %, тир, итог, «бюджет превышен» | шапка активного плана |

### 5.5 Замена блюда

Как сейчас (`x`/`v`/`c`), но: **10 альтернатив** (`MEAL_ALTERNATIVES_LIMIT`,
`database.py:33`) страницами по 5; у каждой — одна причина (M8 §6.6) и дельта
«+120 ₽ / −80 ккал»; после применения — обновлённый день и строка «Покупки
пересобраны». Событие `replaced_*` в `taste_events` пишется репозиторием,
бот ничего дополнительно не делает.

### 5.6 Покупки

| Веб | Бот |
|---|---|
| Группировка по категориям Ленты + «Уточнить в магазине» | «🛒 Покупки»: сначала список категорий с прогрессом «Молочные 2/5», выбор категории → чек-лист; «Все подряд» — сквозной чек-лист страницами по 30 |
| Колонки: нужно купить / есть дома / товар Ленты / цена / упаковки | кнопка `☐ Сметана 20% · 2 уп · 178 ₽`; при нажатии «ℹ️» у категории — развёрнутый текст с «есть дома», ссылкой на lenta.com, числом упаковок |
| «Куплено» | `s:` как сейчас, перерисовка страницы |
| Итого | шапка: «Осталось купить 3 450 ₽ из 4 120 ₽» |
| Позиции «по вкусу» / «уточнить» | отдельная группа «🧂 По вкусу и уточнить» без чекбоксов |

### 5.7 Рецепты

Сцена `recipes.search` («📖 Рецепты», `/recipes`):

- ввод текста = поиск (`GET /api/recipes` логика через `AppRepository`);
  фильтры кнопками `f:`: приём пищи, кухня, тип блюда, «только
  проверенные» — состояние фильтров в `data`; страницы по 8 карточек
  «Название · 35 мин · 4 порции · 🇬🇪 · черновик»;
- карточка (`r:`): мета, страницы книги, ингредиенты, шаги (как сейчас),
  плюс «💰 Цены Ленты» тумблером, **оценка** ★1–5 / снять (`g:`), для
  owner/admin — «✅ Готов / ❌ Отклонить / ↩ В черновики» (`w:`),
  «➕ В план» → выбор дня и приёма активного плана → `replace_meal` с
  этим `recipe_id` (то же, что замена, но с конкретным блюдом; валидация
  допустимости — как сейчас `limit=1000`).

### 5.8 Запасы

Сцена `inventory`:

- «🧊 Запасы»: список по сроку годности страницами по 8, бейджи «просрочен /
  до 05.09 / 3 дня», кнопка 🗑 у каждой (`i:` с `y:` подтверждением);
- «➕ Добавить»: **одна строка свободным текстом**
  `молоко 1 л до 05.09`, `яйца 10 шт`, `курица 800 г морозилка`.
  Разбор в `scenes/inventory.py:parse_lot(text) -> InventoryPayload |
  ParseError` — регулярки: количество + единица (шт/г/кг/мл/л и
  словоформы), дата (`до дд.мм`, `дд.мм.гггг`, `+N дней`), место
  (холодильник/морозилка/шкаф, дефолт холодильник). Нераспознанное поле —
  уточняющий шаг с кнопками (единица, место, «без срока»); пресеты-кнопки
  «Молоко / Яйца / Хлеб / Курица / Рис / Картофель / Сыр / Масло» как в вебе;
- просроченная дата → «Продукт уже просрочен, всё равно добавить?» (аналог
  422 + `already_expired`);
- удаление — с кнопкой «↩ Вернуть» в течение 10 с (аналог undo-тоста:
  отложенный `DELETE` через `asyncio.call_later` в транспорте).

### 5.9 Продукты Ленты

Сцена `products` («/products», ссылка из карточки рецепта): поиск текстом,
категория (`f:` из `/api/products/categories`, страницы по 8), сортировка
(алфавит / дешевле / дороже), «🔥 только со скидкой»; карточка товара:
бренд, фасовка, три цены, скидка, КБЖУ/100 г, ссылка на lenta.com.

### 5.10 Настройки

Сцена `settings` («⚙️ Настройки») — подменю:

| Пункт | Что | Как |
|---|---|---|
| 👨‍👩‍👧 Семья | название, участники, роли | переименовать (текст); список людей → карточка: имя, тип, ккал (или «по формуле: 1 850»), порция, «ест дома: З О У» тумблерами `o:`, «Убрать»; «➕ Добавить» — сцена: имя → взрослый/ребёнок → (M8) дата рождения / пропустить → цель ккал / по формуле |
| 🍳 Техника | 13 кодов | тумблеры `o:` списком 2 колонки, перерисовка сообщения |
| 🚫 Ограничения | правила | список «Аллергия · орехи · строгое · для Маши»; «➕» — сцена: тип (4 кнопки) → продукт (текст) → для кого (вся семья / имя, M8) → строгое? ; удаление `y:` |
| 🎯 Как планируем (M8 §3.4) | режим, дни, бюджет/нед, кухни, лимиты минут, слоты, «на два раза», новизна | по одному полю на шаг, всё с кнопками быстрых значений |
| 😋 Вкусы (M8 §4) | онбординг и сводка | `/taste`: карточки 👍/👎/⏭ (`t:`); сводка «любите: супы, грузинская; не любите: рыба» |
| 🔗 Телеграм | статус, вход в веб, отвязка | «Привязан к `login`», «🌐 Войти в веб» (§3.3), «Отвязать» (§3.4) |
| 📊 Данные | счётчики | рецептов / проверено / источников / товаров |

Сохранение — точечное (`update_person`, `database.py:381`, и новые
`update_appliances` / `update_rules` / `update_plan_profile`), а не полный
`save_settings`: бот меняет по одному полю. Веб может продолжать слать
`PUT /api/settings` целиком.

Тема оформления — единственная функция веба без аналога (не имеет смысла в
Telegram); фиксируется как осознанное исключение.

## 6. Уведомления (только бот)

`notifications.py` — цикл в процессе бота раз в минуту (`asyncio.Task` рядом
с polling), по локальному времени семьи (`LENTA_TIMEZONE`, позже —
`households.timezone`). Настройки — «⚙️ → 🔔 Уведомления», по умолчанию
включены только утреннее меню и сроки:

| Уведомление | Когда | Текст |
|---|---|---|
| Утреннее меню | 08:00 | «Сегодня: завтрак — сырники, обед — борщ, ужин — …» + кнопки 📖/🔁 |
| Вечерний вопрос | 20:30, если у слотов дня нет `status` | «Что приготовили сегодня?» → кнопки ✅/⏭ по блюдам (M8 §4.1 события) |
| Сроки годности | 09:00 | партии со сроком ≤ 2 дней и то, в каких блюдах плана они используются |
| Покупки перед стартом плана | за день до `starts_on` в 18:00, если куплено < 50 % | «Завтра начинается меню, не куплено 12 позиций на 3 450 ₽» + «🛒» |
| План заканчивается | последний день плана, 12:00 | «Составить меню на следующую неделю?» → `plan.new` с предзаполнением |

Таблица `app_core.telegram_notifications(user_id, kind, enabled, hour,
last_sent_on)`; дедупликация по `last_sent_on`. Уведомления не отправляются
пользователям с отозванной привязкой.

## 9. Приёмка

1. Новый пользователь без веба: `/start` → «Создать аккаунт» → семья →
   (онбординг вкуса) → `/new` → план на 7 дней → покупки по категориям →
   отметил 3 позиции → заменил ужин среды на второй из 10 вариантов → в
   вебе (`/web`, код) виден тот же план, те же отметки, `audit_log` с
   `channel='telegram'`.
2. Пользователь веба привязывает бота командой, в боте меняет технику и
   добавляет правило «ребёнок — аллергия — орехи»; `GET /api/me` в вебе
   отражает изменения без перезагрузки контекста бота.
3. Запасы: `молоко 1 л до 05.09`, `яйца 10`, `курица 800 г морозилка`,
   `сыр` — первые три создаются сразу, четвёртый спрашивает количество и
   единицу; просроченная дата — вопрос-подтверждение.
4. Рецепты: поиск «плов» + фильтр «грузинская» + «только проверенные» → 8
   карточек → карточка → ★4 → «В план → четверг → ужин» → план обновлён.
5. Уведомления: утреннее меню приходит один раз в 08:00 по семье; после
   отвязки — не приходит.
6. Безопасность: сообщение в групповом чате не даёт доступа; второй
   Telegram-аккаунт не может привязаться к тому же пользователю; 25
   сообщений за минуту → «Слишком часто, подождите».
7. Любая сцена: «✖ Отмена» и `/cancel` возвращают в главное меню; через 30
   минут бездействия ввод не попадает в старую форму.
8. Все тексты ≤ 4096 символов, все клавиатуры ≤ 100 кнопок — проверяется
   тестами `render.py` на плане из 14 дней и списке покупок из 120 позиций.
9. Ни одна кнопка не оставляет «⏳» дольше 60 с: при ошибке приходит
   сообщение с причиной.

## 10. Не входит

- групповые чаты и семейные чаты (общий доступ через группу) — после
  того, как появятся приглашения в семью (`household_invites`, TZ-M1);
- webhook (остаётся long polling, как решено в TZ-v2);
- голосовые сообщения, фото чеков, распознавание холодильника;
- оплата и заказ в Ленте;
- тема оформления (не имеет аналога).

## 11. Зафиксированные допущения (для ревью владельца)

- А1. Аккаунт из бота создаётся **без пароля**; в веб — по одноразовому
  коду из бота; пароль можно задать позже в вебе. Альтернатива (просить
  пароль в чате) отвергнута: пароль в истории Telegram — плохая практика.
- А2. Бот работает только в личных чатах.
- А3. Свой транспорт вместо aiogram (обоснование в §2).
- А4. «Активный план» бота = последний, пока пользователь не выбрал другой
  в истории; выбор живёт в состоянии диалога, а не в профиле.
- А5. Добавление запаса — одной строкой с разбором, а не пятишаговой
  формой; форма — только для уточнения нераспознанного.
- А6. Уведомления по умолчанию: утреннее меню и сроки годности включены,
  остальные — по желанию.
